# Мониторинг ПБ

Веб-система контроля противопожарного состояния объектов. Её видят две стороны:

- **обслуживающая организация** (роли «Администратор» и «Инженер») видит все объекты, ведёт журнал работ и график ТО, выставляет замечания;
- **эксплуатант**, то есть собственник, арендатор или УК (роль «Эксплуатант»), видит только свои объекты. Он отвечает на чек-лист, загружает документы и подаёт заявки.

## Что умеет

| Раздел | Что делает |
|---|---|
| **Анкета объекта** | Общие сведения, класс ФПО, этажность, огнестойкость, люди, категории помещений, системы ПЗ с годом ввода и сроком службы. |
| **Автоанализ** | По анкете выдаёт предупреждения: нет вывода сигнала на пульт для Ф1.1/Ф1.2/Ф4.1/Ф4.2, истёк срок службы систем или огнезащиты, нет СОУЭ или АПС при массовом пребывании людей. |
| **Чек-лист** | Пп. 1–29 взяты из опросного листа сотрудников, остальные добавляются по системам объекта. Показываются только применимые пункты. Ответ «Нет» сам создаёт замечание, ответ «Да» его закрывает. К каждому пункту можно приложить файл. |
| **График работ** | Регламентные работы по ППР с периодичностью и сроками. Статусы: просрочено, скоро, в норме, нет данных. Периодичность и исполнителя можно менять для каждого объекта. |
| **Журнал** | Выполненные работы и проверки с актами. Результат «Неисправно» сам создаёт критическое замечание. |
| **Замечания и заявки** | Замечания выставляет обслуживающая организация, заявки подаёт эксплуатант. Есть статусы, сроки, фото. |
| **Документы** | Договор на ТО, исполнительная документация, приказы, сертификаты, акты. |
| **План-график** | Сводка по всем объектам на 14–365 дней вперёд. |
| **Регламент ТО по ГОСТ** | Для каждой системы — перечень конкретных операций по ГОСТ Р 59636…59643-2021 (СПС, СОУЭ, АУПТ водяные/газовые/порошковые/аэрозольные, ВПВ, огнетушители и др.) с периодичностью, датой последнего выполнения и сроком. |
| **Акт ТО** | Инженер отмечает по каждой операции: норма / неисправность / не выполнялось, пишет замеры. Неисправность → замечание. Акт печатается с подписями сторон. |
| **Бюджет** | Ориентировочная стоимость ТО систем ПЗ в год и в месяц по рыночным ценам (Москва и МО, 2025–2026), с учётом количества оборудования и периодичности. Цены и коэффициенты правит администратор в разделе «Цены». |
| **Отчёт** | Печатная форма по объекту: можно распечатать или сохранить в PDF с подписями сторон. |

Регламенты ТО по ГОСТ и цены — в **`maintenance.py`**. Вся остальная нормативка собрана в файле **`norms.py`**: анкета, системы, работы, чек-лист, ссылки на пункты. Новую периодичность или номер пункта меняют там, остальной код трогать не нужно.

> ⚠️ ППР № 1479 действуют **по 31.12.2026**. С 2027 года правила утверждает МЧС России. Проект нового приказа повторяет ППР, но номера пунктов сдвигаются. Когда приказ выйдет, обновите поля `ref` в `norms.py`.

## Быстрый старт на своём компьютере

Нужен Python 3.10+.

```bash
pip install -r requirements.txt
flask --app app seed-demo      # необязательно: демо-объекты
python app.py                  # открыть http://127.0.0.1:5000
```

Демо-вход: `admin@demo.ru` / `demo12345` (обслуживающая организация), `client@demo.ru` / `demo12345` (эксплуатант).
Если демо не загружать, при первом входе откроется страница создания администратора.

Проверка, что всё работает: `python tests/test_app.py` → `OK`.

## Работа с системой

1. **Эксплуатанты** → добавьте организацию собственника или арендатора.
2. **Объекты → + Новый объект** → заполните анкету и отметьте системы. Система сама сформирует чек-лист и график.
3. **График работ** → у работ со статусом «Нет данных» внесите дату последнего выполнения.
4. **Пользователи** → создайте вход для эксплуатанта (роль «Эксплуатант», выберите его организацию) и передайте ему логин и пароль.
5. Дальше работа идёт так: инженеры отмечают ТО и проверки, эксплуатант отвечает на чек-лист и подаёт заявки, на главной видно состояние всех объектов.

## Развёртывание на сервере (Docker)

Подойдёт любой VPS с Docker.

```bash
git clone https://github.com/<ваш-логин>/fire-monitor.git
cd fire-monitor
cp .env.example .env     # впишите SECRET_KEY, ADMIN_EMAIL, ADMIN_PASSWORD
docker compose up -d --build
```

Сайт откроется на порту 8000. База и загруженные файлы лежат в папке `data/` на сервере: её нужно регулярно копировать в резерв.
Для доступа по домену и https поставьте перед приложением nginx или Caddy, затем задайте `SESSION_COOKIE_SECURE=1`.

**Персональные данные.** В системе хранятся ФИО и телефоны. По 152-ФЗ персональные данные граждан РФ должны храниться на серверах в России, поэтому берите российский хостинг.

## Демо-версия (один файл для GitHub Pages)

`demo/index.html` — та же система без сервера, данные хранятся в браузере. Собирается командой
`python build_demo.py` из папки `demo_src/` и `maintenance.py` (регламенты и цены общие с полной версией).

## Структура

```
app.py          — веб-приложение (маршруты, права, логика статусов)
norms.py        — нормативная база: анкета, системы, работы, чек-лист
maintenance.py  — операции ТО по ГОСТ и цены для бюджета
build_demo.py   — сборка демо-версии demo/index.html
schema.sql      — структура базы данных (SQLite)
seed.py         — демо-данные
templates/      — страницы
static/style.css
tests/test_app.py
```
